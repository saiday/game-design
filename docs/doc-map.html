Insignificant · Documentation Map

What each document is for, who reads it, and how they connect. Companion to the development dashboard.

Layout rule: one docs/ tree per level. Repo-root docs/ holds cross-project doctrine, process docs, and human dashboards. insignificant-game/docs/ holds the build contract and working docs. insignificant-game/design/ holds the game rules and is the single source of truth. Agent navigation lives in the two CLAUDE.md files (the root one carries the routing matrix); this page is the human-facing view of the same structure. Update both when a document is added, moves, changes role, or is removed.

Maintenance rules (the short version)

  • Current state only. Docs describe the present, written for fresh eyes. History lives in git commit messages. Exceptions that keep dates, all purpose-built logs: PLAN.md, decisions.md, implementation-notes.md, the exploration logs, prompts.md, everything under docs/depandabot/, the cookbook §14 findings log, and license/verification records.
  • Single source of truth. Game rules live in design/ and nowhere else; other docs link instead of restating. The contract (architecture.md) fixes code shape, not rules.
  • Bidirectional metadata is machine-checked. Design frontmatter code: lists, module header citations, the graph: feed edges, and this page's registry coverage are all verified by insignificant-game/docs/tools/check_design_graph.py, which runs as Part A of the dev loop. Errors fail the run; an asymmetric feed edge is reported as a warning because resolving it is a design call, not a mechanical one.
  • Skill-pinned paths. docs/adr/ and docs/agents/ are read by installed skills at those exact paths; never rename them.
  • Known absences are declared, not discovered. The routing matrix in the root CLAUDE.md distinguishes out-of-scope-by-design (multiplayer, save/load) from planned-but-pending (audio/music pipeline, localization workflow) so agents can tell intentional absence from missing docs.
  • When a doc is added, moved, re-roled, or deleted: update the root CLAUDE.md routing matrix and this page together, and bump both dashboards' footers. A new doc that belongs to a cluster already mapped here (a setting doc, an ADR, an audit) is covered by that cluster's row; a new kind of doc needs its own. Forgetting the row is now a Part A failure, not something a later reader has to notice: the coverage check walks every doc-shaped file in the repo and requires either its own row or a cluster row that covers its directory.
